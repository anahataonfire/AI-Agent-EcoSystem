Order lifecycle

Automatic and manual reconciliation

While live mode is enabled, each dashboard order poll fetches the authenticated trade ledger once, filters it per local order, applies order snapshots, and aggregates confirmed trade IDs. The Orders view also exposes a manual Reconcile action. Cancellation changes local state only when the exchange response lists that exact order ID in canceled.

Profit screen

The 90-95¢ entry band is a configurable forward test. It is not a proven edge. The market must accept orders. The fee must be known. Settlement basis must be trusted, unless an exact station has already eliminated the bucket. Risk, exposure, payoff, book depth, and the fresh quote must also pass their configured limits.

Fee modelFor a taker buying C shares at price p, the modeled platform fee is C × feeRate × p × (1 − p). Post-only maker orders model zero platform fee. Builder fees are outside this model unless separately configured.

New opportunity classes

  • Exact-station hard bounds: only a market rule that names a weather.gov station can eliminate a bucket. Wunderground and unknown sources remain inert.
  • Complete-set signals: all YES buckets must share one Gamma event ID, include both tails, cover the integer range without gaps or overlaps, accept orders, and remain profitable after fee and slippage guards. Signals are non-executing by default.
  • Maker cohort: post-only orders join a non-crossing bid and remain reservations until confirmed; they can improve fee economics but introduce fill-selection risk.

Paper mode writes only the local run log. Synchronizing a live-run summary to bdc-fabric requires explicit --sync-bdc-fabric; dry-run cannot trigger that external write.

4. Before live mode

  1. Reconcile or cancel the 36 legacy LIVE orders; their $2,391 reservation currently exceeds the configured $1,000 bankroll.
  2. Complete a fresh scan and confirm fee, station provenance, accepting-orders, book depth, and event exposure.
  3. Keep the cohort small until verified fills resolve and both realized ROI and calibration clear a predeclared threshold.

Override controls

No new strategy default is a hidden lock. Runtime settings expose bankroll, opportunity cap, event cap, maximum scan age, re-quote tolerance, and default order mode. Automation exposes bidirectional boolean flags such as --allow-open-buckets/--no-allow-open-buckets. API trade gates accept override:true for deliberate one-offs; absence of a live quote and missing authenticated identity remain execution errors, not tunable preferences.

Known validation boundary

Offline regression covers lifecycle transitions, fee math, hard-bound provenance, complete-set coverage, canonical event exposure, maker pricing, and provisional/verified backtest separation. A current live dry scan was stopped after roughly 75 seconds while upstream forecasts were still loading, so current-market candidate counts and live nowcast availability remain unverified in this release.
